## 实测推动的修复

- QQ OAuth iframe、163 跨域密码框不再被顶层 DOM 检测遗漏。
- 用户名输入框不作为已登录身份标志。
- 不强求页面到达 `complete`，避免资源未加载完阻断已有页面操作。
- 空白页仅允许导航恢复，登录页仍拦截普通动作；done 可直接结束。
- 显式断开 CDP，保留外部 Chrome；生命周期实测正常退出，不触发自动重连。
- 本地测试改用独立 Chrome + CDP，避免 browser-use 本地异步进程管道清理警告。
- 移除测试脚本基于过期标签 URL 自动关标签的逻辑，避免误关正在导航的页面。
- 完成规则增加全文数量与格式自检。自然语言约束由模型执行，不代表确定性保证。
- 实时页面已有账号与会话标记且无登录阻碍时，拦截由旧空白快照触发的 handoff，要求模型先只读检查当前页面。27 项 Python 测试通过，包括这一误暂停场景；本项后续飞书实网复测因 CDP 重连超时未完成。
- GitHub 登录成功页没有可见“退出登录”文字时，使用 `meta[name="user-login"]` 作为站点专用成功标志；仍保留 `/login` 路由阻断，避免将登录页误判为已认证。
- 站点专用成功标志已配置化为 `login_state.js` 内的规则表；新增特殊站点时只需增加 host/path/selector/meta 配置，不再扩展认证结果联合表达式。未知网站仍优先使用通用规则或 `--login-success-selector`。
- 通用检测结果增加 `authEvidence` 和 `confidence`：分别记录可见退出控件、账号身份、会话标志、配置选择器或站点规则等证据，并以多证据组合提高置信度；单独 Cookie、头像或普通页面不会直接放行。
- 本地 `explore_live.py` 对指定 Chrome profile 增加进程锁，拒绝多个 agent 同时连接同一 profile，避免 CDP target detach 和重复响应。
- Chrome 启动等待改为确认 `/json/version` 可访问后再连接，降低 profile 已存在或 CDP 刚启动时的连接竞态。
