# 织语 Benchmark 下一步计划

2026-10-08：以下为9月30日制定的阶段计划；已执行进展及下一步顺序以 `PROGRESS_20261008.md` 为准。实际DB元数据和公开样本、独立UI见证、映射v3、54项契约冻结、6次受控采集及A评分均已完成；B的111个状态/222份产物已收卷并全部通过schema，使用Flash，引用诊断及事后路径兼容诊断已完成。完整语义裁定与全trace忠实度仍是缺口。原“等待专用浏览器”“阿器模型待核验”等描述是历史待办。

## 当前事实与目标

当前答案是“参考既有DB语义清单、结合历史候选词表、由独立网页证据核验”的有限核心契约，不是本轮从真实数据库重新导出并逐项核实的实体/属性全集。coverage-v3已修复部分UI证据误计，但不证明DB映射正确。已有A结论限于历史UI材料覆盖，B仅完成声明召回及格式/引用检查。

继续回答两个问题：A 哪种探索策略采到更丰富且可靠的业务证据；B 同一份原始任务材料下，阿器与Claude Code搭配Flash哪个抽取更完整、准确。保留原始任务、只读范围、现有trace与候选；不恢复已取消的强制重复采集，不新增探索算法。

## 1. 补实数据库到界面的标准答案链路

首先定位现有DB参考答案的生成脚本、查询记录或schema导出，确认来源与版本；若资料不足，再只读连接数据库取得schema/必要样本。不能仅凭catalog_product等语义名称就宣称是真实物理表。

每个候选记录：业务实体/属性、物理表列或EAV属性、关联方式、界面见证、可达前置条件、纳入/排除/待核验理由。DB字段、UI派生值、表单输入、操作入口、状态分开。商品、分类、只读购物车范围内的候选逐项处理，包括两边都没采到的项。购物车明细/金额/写后状态不自动纳入本轮。

产出：`ground-truth-vnext/db-ui-mapping.json`、范围说明、标准答案新版本与冻结清单。验收：每个纳入项都有来源和可达证据；物理映射未知明确标注；不把任意DB列直接放进UI分母。不覆盖coverage-v3。

## 2. 将证据支持纳入打分，分别完成A与B

A保持原始trace直接评分。继续核验API响应和页面事实的对应关系，将UI证据与network证据分列；有明确来源绑定才计入联合覆盖，不混入静态模板或别页响应。评估数据丢失对各事实的影响，未知不当不存在。

B沿用26页TASK/schema/inputs，对实体、属性、操作归属和api_refs逐项裁定为支持、矛盾、未确定；仅有同名字段不能得有证据命中分。范围外合理声明不自动判错，原schema未要求实体间关系时不扣关系分。记录裁定位置、证据和理由。

指标：有证据召回=被证据支持的不同目标事实/该输入可支持的目标事实；已裁定精确率=支持的声明/(支持+矛盾的声明)，同时报告未确定声明数与裁定覆盖率。名称别名、去重单位和范围外处理在计分前冻结。候选已存在，仍标明事后评估，不能称盲测。

补对抗测试：伪造引用、错页引用、静态模板作数据来源、相邻无关值、实体错归属、同义词、重复声明、合理范围外声明。产出新版评分脚本、逐项裁定JSON、测试与新报告。

## 3. 补齐证据质量及成本表

从现有日志核验页面/动作/响应对应、分段失败与缺失；缺少完整动作链的事实保留未知。当前标题一致性只作辅助，不称完整忠实度。

分开核算探索阶段与抽取阶段，统一记录墙钟区间、有效运行时间（可得时）、模型请求/重试/超时、token与账单费用来源。阿器历史模型路由需核验；Claude的35分钟用户口径和约145分钟日志区间分列解释，不混算。不可恢复的账本指标记未知，不估成零。

产出：来源可追溯的 `cost-ledger.json` 及“覆盖—证据质量—成本”对比表；预算不一致时不声称同预算效率优胜。

## 4. 最终交付

输出A/B各自结论与逐项依据，明确胜出的具体维度、未决项及实验限制；提供一个索引指向当前有效版本、标准、评分器、候选、原始trace、冻结清单和报告。将路径改为命令行参数，锁定依赖版本；验证干净输出目录复算，防止覆盖冻结输入。

若历史数据不足以支持总体排名，报告明确给出有依据的工程建议与剩余不确定性。只有需要新增采集、改变权限/购物车范围或扩大预算时再请用户决定；不以无法补齐历史日志为由自行重跑。

## 执行顺序

数据库/界面来源核验 → 冻结新答案与评分规则 → 现有A/B重新评分 → 补齐质量与成本 → 最终结论及可复算入口。成本日志整理可在来源核验期间开展。当前不承诺完成日期，先确认现有DB来源材料是否足够。
