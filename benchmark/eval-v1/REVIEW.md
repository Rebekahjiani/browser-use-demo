# Benchmark 对抗式审查与执行契约

日期：2026-09-29。原始沙箱文件保留。新增文件位于 benchmark/eval-v1。

## 结论

目标有意义：在固定预算内，比较探索得到的可验证业务语义，以及同一证据经不同构建器后的保真度。当前材料能支持试评，不能支持正式优劣排名，也不能支持“全站还原率”。DB 是持久化数据的依据，不是页面行为或全部业务语义的唯一真相。

## 已完成

- ground-truth/shopping.ui-core.v1.json 冻结已证实最小核心（3 实体、8 属性、6 个可见操作、2 关系），附页面、AX 节点、DB 映射、名称别名、前提条件和 SHA256。冻结的是这个窄范围，不代表三个模块全集。
- schema.json 复用沙箱抽取契约，增加关系、操作可见性等级与必要字段校验。
- prepare.py 将现有两策略材料转换成共用 UI-only 任务包；TASK/schema 字节相同，输入证据保留来源哈希；所有快照保留，不把同 URL 当新页面类型。
- collect.py 验证 schema、引用、实体归属、关系端点、空 API 引用后统一收卷。此文件输出仍保留逐页概念，评分时应按业务映射取集合去重。

## 原打分器不可直接使用的原因

1. expected 要求 entities 数组，而旧标准答案是对象；属性读取 name，而旧标准答案用 code。
2. 未应用 ui_derivable 过滤；实体内 21 处计数仍是修订前统计。
3. 属性召回分母仅包含命中实体，遗漏整类实体不扣属性分。
4. 没有中文/DB 字段同义词映射、逐页合并、多表到单业务实体映射。
5. 不能评关系、操作、证据真实性；未经匹配的输出被直接判误报，混淆别名、合法范围外概念与幻觉。

因此 compare-cm.ts 仅保留作参考，不用它发布分数。新标准的别名用于评测方映射，不提供给生成 agent。下一版打分器须对映射冲突报人工复核；未匹配项先列 unmatched，不自动称为 hallucination。

## 正确指标

- 全局属性召回 = 命中的预期实体-属性对 / 全部预期实体-属性对；遗漏实体的属性也在分母。
- 实体/操作/关系分别计集合召回；重复页与同义词不重复得分。
- 精确率须先裁定 unmatched 是否真实错误；不能仅凭 DB 无表判错。
- 提取召回 = 从 trace 成功抽取的事实 / 人工确认该 trace 实际包含的参考事实。
- 探索覆盖 = trace 实际包含的参考事实 / 冻结的范围内参考事实。
- 两者分开报告，避免采集遗漏归因于构建器。固定构建器的最终分只是端到端代理指标，不是纯探索能力。

## 最强反驳与约束

### 分母偏向某策略
当前核心用 browser-use 既有快照核验，存在选择偏差，只能试评。正式分母必须在新测试运行前，通过独立人工参考采集覆盖三个模块，冻结版本；不能根据被测结果增删分母后重排旧名次。

### 记录数量不等于覆盖
10 万商品无需逐个爬取。计页面类型、业务状态与事实；同类商品重复页不给额外语义分。没有状态清单时只报发现数量，不报全站覆盖百分比。

### “200轮”不公平
LLM step、drive loop、浏览器动作分别记录。200轮/100页/30分钟是预算组合而非等价工作量。建议主比较固定30分钟并保留统一执行动作上限，附5/10/20/30分钟覆盖曲线；提前done保留为结果，不偷偷续跑。成本包含模型调用、token、失败重试与实耗时间。

### 策略之外有观测差异
browser-use AX 与 drive ARIA 来源不同，统一 ui.json 并不消除传感器差异。本版比较完整采集系统；要声称仅探索算法更优，必须统一执行/观测与采集器。drive 现有备料可能只保留每页一份结构，browser-use有多个快照，报告中应披露。

### 只读策略看不到写后状态
统一允许搜索/筛选/排序/分页等读取交互；购物车增删改另设可重置实验轨。每次恢复相同 DB、登录、cookie、购物车和站点版本。可见按钮与成功执行分别评分。当前包只能评 visible_control。

### 证据质量影响归因
两份旧运行都有 dataLossOccurred=true。逐项检查缺失是否触及评测事实；不要仅凭标记废弃全部数据，也不要据此声称完整。UI-only首版不评API；后续API轨必须双方走同一端点归一化流程，不能只给一方 endpoints。

### 模型与提示词混杂
旧browser-use提示词直接指定商品等概念，织语逐页任务没有同样引导；旧结果不得直接对比。使用本版TASK/schema重新生成；不喂 history中的agent总结、不喂ground-truth。记录请求实际模型ID，网页勾选和settings默认值均不足以证明运行模型。

### 统计结论过强
每策略至少3次独立重置运行，报告全部原始值、中位数与范围，3次不足以证明显著性。构建器固定同一组多样trace，每份至少重复2次；不能只挑某策略最好的一份trace。
