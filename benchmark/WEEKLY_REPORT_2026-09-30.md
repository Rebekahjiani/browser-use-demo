# Benchmark 周报

报告周期：2026-09-24 至 2026-09-30  
项目：织语 / browser-use Shopping Benchmark

## 一、本周结论

本周完成了 A（自动探索采集）和 B（Context Model 抽取）两条评测线的阶段性冻结、复算和文档收口。当前可以给出有限范围的工程选型判断，但还不能把结果解释成全站覆盖率、完整语义准确率或严格的速度/费用排名。

## 二、本周进展

### 1. 自动探索评测（A）

- 完成 coverage-v3 规则修订和原始 trace 重评，收紧了属性值、筛选/分页、购物车页面、关系和证据指针的判定条件。
- 在当前有限 UI 契约下，Drive 的有值/选项核心属性为 **29/29**，browser-use 为 **16/29**；核心实体为 **2/3 vs 3/3**，核心页面类型为 **4/6 vs 5/6**。
- 完成两层标准答案的 DB 来源核验：DB 字段子集两边均为 **6/6**；业务细节层为 **29/29 vs 16/29**。因此不能把属性层差异直接解释成 DB 字段覆盖优势。
- 完成一次 browser-use 补充采集：5 个 URL、14 份快照、30/30 个 tracer 分段完成，`dataLossOccurred=false`；采集期间保持访客空购物车和只读约束。
- 结论：以业务属性证据丰富度为目标时，本轮暂优先 Drive；browser-use 在购物车页面覆盖和记录完整性方面更好。不合成总分，也不宣称算法普遍胜出。

### 2. 抽取与 harness 对照（B）

- 固定同一份织语 26 页任务包，确认 81 个 TASK/schema/input 文件哈希一致。
- 完成阿器与 Claude Code 的历史产物比较、schema 检查、引用支持诊断和成本日志整理。
- 当前自身引用支持核心召回为 **30/32 vs 22/32**，v4 评分测试 7 项通过；该指标不等于完整语义精确率。
- 两边日志均记录 `DeepSeek-V4-Flash-0731`。阿器记录 89 次完成模型调用，Claude Code 记录 171 个去重 assistant message ID；两种日志口径不同，不能直接当作 HTTP 调用数比较。
- 发现并记录关键限制：候选和答案存在事后标注偏差，Claude 会话包含重复提示/压缩，模型上下文与重试行为未完全控制。

### 3. 数据、工具与文档

- 新增 DB/EAV 到 UI 的映射和双层评分工具，完成 4 项双层评分测试。
- 整理 B 的 v2/v3/v4 引用评分脚本及成本账本，保留冻结输入和可复算命令。
- 将 benchmark 文档收敛到当前计划、当前结果和下一步三个入口；旧计划、旧结论、旧 prompt、pilot 和 handoff 文档移入 `benchmark/archive/`，删除重复状态页。

## 五、风险与待确认

- 当前 A/B 结果仍是有限范围、历史运行和单次/非完全控制变量条件下的诊断，不代表全站能力。
- DB 中存在多个 UI 细节共用 description 字段的情况，不能把每个 UI 文案机械视作独立 DB 字段。
- 现有 token 记录尚未与供应商账单对齐；下周如需费用结论，必须补充统一账单口径。
- 正式发布前仍需完成语义精确率、trace 忠实度和多次独立运行的验收。
